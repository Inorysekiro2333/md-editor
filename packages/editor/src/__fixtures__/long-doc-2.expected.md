## 依赖关系

* M1 编辑内核是后续一切工作的前提：
  * cursor-map 依赖内核稳定：
    * 模式切换用光标恢复（R3）
    * 拖拽排序用节点路径
  * 序列化差异登记依赖内核行为固定
    * 未登记差异一律视为回归
    * 差异注释使用 Registered normalization 标记
* M3 工作台依赖 M2 的源码模式：
  * 标签页需要无丢失切换
  * 查找替换跨两种模式
    * 渲染模式替换后重新解析
    * 源码模式直接文本替换
* M4 依赖 M1 至 M3 全部完成
  * 主题依赖 DESIGN.md 的 token 定稿
  * 导出依赖主题渲染结果
* M5 依赖全部里程碑验收

## 风险清单

1. IME 组合输入在表格单元格中的行为未验证
2. 大文档（超过 2000 行）的惰性渲染方案未定稿
3. watch 事件回环需要写入凭证加 500 毫秒兜底
4. getMarkdown 的空行规范化可能与用户习惯冲突
5. 中文标点与强调符号相邻时的解析歧义
6. 表格单元格内换行只能依赖 br 标签
7. 自动更新在三平台的签名要求不同
8. 主题变量数量过多会拖慢主题检查脚本

## 名词解释（续）

1. **投影**：渲染层文档树由 Buffer 派生，不反向写回。
2. **收敛**：键入事务在防抖窗口内把 PM Doc 的临时状态同步回 Buffer。
3. **窄接口**：preload 只暴露白名单方法，渲染进程无法直接访问 fs。
4. **净室**：不看竞品实现代码，只依据公开行为设计。
5. **惰性渲染**：视口外的重型块延迟创建。
6. **写入凭证**：主进程写文件时记录指纹，watch 收到匹配事件即忽略。

以上内容用于大文档往返测试，正文到此结束。
